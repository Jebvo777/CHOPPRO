# ЧОППРО

Рабочий Core MVP Этапа 2: backend PHP 8.3/PDO, MySQL 8, веб-приложения администратора ЧОП, заказчика и оператора платформы. Дополнительно реализована биржа труда с ручным закрепом трёх вакансий.

Портал проекта получает документацию и исполняемый код из `main`. Отдельные приложения открываются кнопками «Демо администратора», «Демо заказчика», «Демо платформы», «Демо биржи труда». Кнопка «Актуализировать БД» создаёт структуру и наполненные тестовые данные, а затем применяет новые миграции без повторного заполнения.

## Что работает

- Изоляция организаций, роли и права, области объектов, приглашения, блокировка, MFA TOTP, OTP охранника, ротация сессий, временный доступ поддержки.
- Сотрудники, документы, типы документов, приватные файлы, карантин ClamAV, ручная проверка, статусы срока и однократные напоминания.
- Лицензии, договоры, версии справочников и шаблонов, проверка реквизитов, задачи по рабочему календарю, подтверждения и черновики для ручной подачи, хранение договоров, личные карточки.
- Заказчики, объекты, круговые и полигональные геозоны, посты, версии инструкций, QR с отзывом.
- Смены, повторяющиеся шаблоны, публикация, назначения, подтверждения, пересечения и разряд, замены, предупреждения о нагрузке.
- Серверное присутствие: GPS/QR/временное окно, исходное и серверное время, офлайн-признак, идемпотентность, ручные решения, неявки и длительность.
- Кабинет заказчика: только свои и опубликованные данные, обходы, происшествия, отчёты, PDF и ознакомление.
- Биржа труда: поиск вакансий, закреп №1–3, отклики работодателю.
- Аудит, мягкое удаление, импорт с предпросмотром и откатом, защищённый CSV-экспорт, состояние платформы.

Тестовая база: 5 организаций, 1000 сотрудников, 3000 документов, 120 объектов, 360 постов, 10080 смен и 80 вакансий с связанными операционными данными. Пароль исходных демо-аккаунтов `Demo2026!`; основной администратор `admin@obereg.example`, заказчик `customer@obereg.example`, платформа `platform@choppro.example`.

## Установка и приёмка

- [Установка на shared hosting](docs/Этап_2_установка.md)
- [Проверка Этапа 2](docs/Этап_2_приемка.md)
- [Матрица требований](docs/Матрица_требований_ЧОППРО.csv)

Сборка архива: `python3 tools/build_hosting.py --sha <SHA-коммита> --output dist/CHOPPRO_stage2.zip --private-config <приватный-site.php>`. Приватные настройки передаются вне Git. PHP 8.3+, PDO MySQL, mbstring, curl, fileinfo, GD и OpenSSL обязательны.

Для backend вне портала: задать `DB_HOST`, `DB_PORT`, `DB_DATABASE`, `DB_USERNAME`, `DB_PASSWORD`, `CHOPPRO_STORAGE_ROOT`; выполнить `php backend/scripts/stage2-migrate.php`. Фоновая обработка: `php backend/scripts/worker.php` каждую минуту. Для настоящих SMS и новых файлов подключаются HTTPS SMS-адаптер и ClamAV; при недоступном сканере файлы остаются в карантине. Подробности в инструкции.

## Структура

| Каталог | Назначение |
|---|---|
| `backend/src/Stage2` | PHP/PDO бизнес-логика и API |
| `backend/database/stage2` | Версионные миграции и метаданные ресурсов |
| `backend/scripts` | Миграции и фоновый обработчик |
| `web` | Отдельные веб-приложения |
| `acceptance-portal` | Портал документации, демо и управления |
| `host-loader` | Стабильная загрузка полных версий без замены работающих PHP-файлов |
| `tools` | Сборка shared hosting и проверки поставки |
| `docs`, `prototypes` | Проектная документация и прототипы Этапа 1 |

Основная ветка — `main`. GitHub Actions проверяет синтаксис, MySQL-сценарии, прерванные обновления и браузерные действия. Автоматическая публикация на портале разрешена только после успешной проверки **Stage 2 acceptance** того же коммита. Незавершённое обновление оставляет предыдущую целую версию; новые миграции запускает владелец, а не посетитель.

Нативные Android/iOS-приложения — Этап 3. Расширенные мобильные процессы и окончательная нагрузочная/эксплуатационная приёмка — последующие этапы по согласованной матрице. Платный аукцион закрепа пока не включён. Подписанные PDF проекта не загружались.
