# Этап 2: установка и эксплуатация

Установочный ZIP содержит готовый портал и четыре самостоятельных приложения. Laravel не используется. Общий backend — PHP 8.3 и PDO, база — MySQL 8. Код, интерфейсы, документация и список демо поступают из `Jebvo777/CHOPPRO`, ветка `main`.

## Shared hosting

1. Сделать резервную копию текущего каталога портала.
2. Распаковать архив в каталог сайта с сохранением скрытых `.loader`, `.private` и `.htaccess`. Прежний портал можно заменить целиком. Данные приложения находятся в `.private/runtime`, будущие автоматические обновления их не заменяют.
3. Выбрать PHP 8.3 или новее. Нужны `pdo_mysql`, `mbstring`, `curl`, `fileinfo`, `gd`, `openssl`.
4. Открыть `control.php`, войти паролем владельца из установочной инструкции и нажать **Актуализировать БД**. База должна уже существовать; создание самой базы или удаление чужих таблиц не выполняется.
5. Вернуться на портал и открыть нужное демо. Все ссылки открываются в новой вкладке. Интерфейс портала не входит в интерфейсы приложений.
6. Настроить cron каждую минуту: `/путь/к/php /полный/путь/к/порталу/site-cron.php`. Он проверяет GitHub, сроки документов, карантин, задачи контроля и неявки. Обработчик также можно запустить из управления порталом или состояния платформы.

Настройки БД, пароль владельца и ключ шифрования хранятся в приватной области. Пароль БД не публикуется в Git. Для отдельно установленного backend конфигурация задаётся переменными `DB_HOST`, `DB_PORT`, `DB_DATABASE`, `DB_USERNAME`, `DB_PASSWORD`, `CHOPPRO_STORAGE_ROOT`.

Apache должен разрешать `.htaccess`. Для Nginx закрыть приватные каталоги и установочную инструкцию до публикации:

```nginx
location ~ /\.(private|loader)(/|$) { deny all; }
location ~ /(INSTALL|installation|site-config|source-metadata) { deny all; }
```

В shared hosting без `mod_rewrite` работают ссылки `demo.php?app=admin`, `demo.php?app=client`, `demo.php?app=platform`, `demo.php?app=jobs`. Дополнительные красивые адреса `/demo/admin`, `/demo/client`, `/demo/platform`, `/demo/jobs` включаются правилами Apache.

## Актуализация БД

Миграции находятся в `backend/database/stage2/NNN_*.sql`. У каждой применённой миграции сохраняется SHA-256. Уже применённый файл менять нельзя: каждое следующее изменение оформляется новым номером. Повторный запуск пропускает применённые миграции и не перезаполняет таблицы.

Первичная загрузка тестовых данных выполняется одной транзакцией, временно отключает проверку внешних ключей и восстанавливает её в `finally`. Маркер установки исключает повторное заполнение. Таблицы имеют префикс `cp_`; существующие несвязанные таблицы не удаляются. Одновременные миграции сериализуются через `GET_LOCK`.

Если обновление требует новую схему, портал покажет новый комплект, а демо продолжит работать на совместимой версии до нажатия кнопки актуализации. После успешной миграции демо переключится на новую версию. Актуализация доступна только владельцу портала и требует CSRF-токен.

## Автоматическое обновление

Стабильный небольшой загрузчик открывает файлы из неизменяемой директории конкретного коммита. Новая версия сначала полностью скачивается, проверяется по Git blob SHA, проходит проверку формата и требований PHP. В `main` должна успешно завершиться проверка **Stage 2 acceptance** для этого же коммита. Только после этого атомарно заменяется указатель рабочей версии.

PHP-файлы, которые исполняет текущий запрос, не перезаписываются. Кэш OPcache получает новые пути. При обрыве соединения, несовпадении суммы, ограничении GitHub или несовместимой версии PHP продолжает работать предыдущий полный комплект. Предыдущие версии остаются доступными для открытых страниц и отката кода. Откат кода не откатывает базу.

Проверка выполняется при посещении приложений/портала и через cron. Интервал — 5 минут. Для большого числа обновлений можно задать серверный `CHOPPRO_GITHUB_TOKEN` с чтением репозитория; токен не передаётся браузеру. Публикация новой функциональности в Git после успешного CI не требует повторной загрузки архива. Изменение протокола самого стабильного загрузчика требует отдельного обновления загрузчика.

| Оператор платформы | `platform@choppro.example` |

Пароль всех исходных тестовых аккаунтов — `Demo2026!`. Тестовые организации: `obereg`, `garant`, `rubezh`, `forpost`, `vector`; для остальных организаций меняется часть после `@`. В демо тестовый MFA-код возвращается только после правильного пароля для специально помеченного аккаунта. Рабочие администраторы подключают приложение TOTP. Аккаунты различных веб-приложений используют отдельные cookie-сессии и могут работать в нескольких вкладках одновременно.

## Внешние сервисы

Для настоящих SMS задаются `OTP_PROVIDER_URL` и `OTP_PROVIDER_TOKEN`. HTTPS-адаптер отправляет JSON `phone`, `code`; поставщик должен вернуть успешный HTTP-статус. Без поставщика рабочий OTP не имитирует отправку. Для тестовых охранников в режиме демо доступен демонстрационный код.

Новые файлы проверяются ClamAV через `CLAMAV_HOST`/`CLAMAV_PORT` (протокол INSTREAM). Допустимы PDF, PNG, JPEG, до 10 МБ. При недоступном сканере файлы остаются в закрытом карантине; скачивание и положительная ручная проверка блокируются. После подключения сканера cron повторяет проверку. Исходные демонстрационные изображения синтетические и поставляются вместе с приложением. Для рабочей системы установить `demo=false`, подключить SMS и сканер и заменить тестовые данные.

Подписанные PDF проекта в эту поставку не добавлялись. PDF отчёта заказчика создаётся динамически из опубликованных данных по запросу авторизованного пользователя.
