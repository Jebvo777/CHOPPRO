# Спецификация API ЧОППРО

Актуальный контракт реализованного этапа 2 — [OpenAPI 2.1.0](openapi.yaml). Базовый путь `/v1`, формат JSON UTF-8. Статус ошибки передаётся HTTP-кодом; тело содержит `code`, `message`, дополнительные сведения и код обращения. Плановые методы мобильного этапа не обозначаются как реализованные.

## Авторизация и транспорт

API принимает Bearer-токен или отдельную сессию приложения. Имена cookie: `choppro_app_admin`, `choppro_app_client`, `choppro_app_platform`, `choppro_app_jobs`. Изменяющий запрос браузера передаёт `X-CSRF-Token`, полученный через `GET /v1/csrf`, включая вход и отклик на публичную вакансию. Для Bearer-запроса CSRF не требуется.

В портале тот же API вызывается через `/demo-api.php?space=admin&path=/v1/employees`. `space` выбирает приложение, а `path` — метод API; HTTP-метод, тело и заголовки сохраняются. Изоляция определяется авторизованным пользователем. Параметр `tenant` применяется только оператором платформы; бизнес-данные выбранной организации доступны после открытия временного доступа поддержки.

Вход: `/auth/login`, `/auth/mfa/verify`; одноразовый код: `/auth/otp/request`, `/auth/otp/verify`; ротация: `/auth/refresh`; приглашение: `/auth/invite`; выход: `/auth/logout`.

## Ресурсы и версии

Списки поддерживают страницы, размер страницы до 500, поиск, статус, сортировку и фильтры связей. `/schema` возвращает разрешённые ресурсы, русские названия, обязательные поля, статусы и ссылки. Изменение записи требует текущего `version`; устаревшая версия возвращает 409. Исторические события не изменяются через обычный CRUD. Мягкое удаление скрывает запись из рабочих списков.

Специализированные методы загружают и проверяют документы, активируют договор, выпускают новую версию справочника, формируют черновик задачи, публикуют/отменяют смену, заменяют сотрудника и сохраняют ознакомления. Скачивание и экспорт проверяют отдельные права и те же ограничения организации/объектов. PDF выдаётся только для опубликованного отчёта.

## Присутствие

`POST /attendance` принимает назначение, CHECK_IN/CHECK_OUT, исходное время, GPS, точность, устройство, QR и ключ повторной доставки. `Idempotency-Key` может передаваться заголовком или `idempotency_key` в теле. Ключ 8–128 символов; повтор с прежним содержимым возвращает исходную запись, изменённый повтор — 409.

Сервер проверяет круг или полигон объекта, точность GPS, активный QR, временное окно, назначение и порядок событий. Спорная отметка получает REQUIRES_REVIEW. `/attendance/{id}/override` сохраняет отдельное решение с причиной; исходное событие остаётся неизменным. `/presence` возвращает начало, завершение и длительность подтверждённого присутствия. `/analytics` показывает плановое покрытие за день и фактическое покрытие постов, работающих сейчас.

## Платформа, аудит и хранение

`/tenants`, `/tenants/{id}/limits`, `/health/platform` управляют организациями, модулями, ресурсами и состоянием обработки. Создание пользователя, сотрудника, объекта и загрузка файла проверяют лимиты атомарно.

`/support/access` открывает доступ по причине на 1–30 минут; `/support/status` проверяет срок; `/support/close` отзывает доступ. Вход поддержки отображается заказчику в аудите. `/audit` фильтруется по организации, объекту, пользователю, разделу, действию, записи и датам, поддерживает страницы; `/audit/export` экспортирует выбранные события.

`/retention` показывает трёхлетнюю политику и историю. POST применяет правила: администратор обрабатывает свою организацию, оператор — выбранную или всю платформу. Фоновый обработчик запускает очистку не чаще одного раза в день; повторное удаление недоступного файла выполняется отдельно.

## Этапы

Внешняя доставка SMS, почты и иных уведомлений подключается **на этапе 4 при подключении платных сервисов**. Внутренние события и контроль сроков работают на этапе 2. Нативные мобильные интерфейсы — этап 3. Публичная биржа труда и ручной топ-3 закрепов входят в текущую реализацию; денежный аукцион не включён.
