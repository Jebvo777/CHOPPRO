# Протокол проверки прототипов Этапа 1

## 1. Объем

Проверяются low-fidelity прототипы, предназначенные для подтверждения структуры, навигации и пользовательских сценариев. Они не являются финальным UI/UX дизайном и должны быть заменены/детализированы после подготовки Figma-макетов.

## 2. Обязательные контуры

Admin: Login/MFA, Dashboard, Employees, Employee, Documents, Customers, Facilities, Posts, Schedules, Shift, Attendance review, Patrols, Incidents, Reports, Audit, Settings.

Mobile: OTP login, Home/next shift, Shift details, Check-in/out, Patrol, QR scan, Incident create, Offline queue, Profile/consents. В проекте PWA заменена отдельными Android/iOS приложениями React Native.

Client: Login/MFA, Dashboard, Facility, Coverage, Published incidents, Reports, Acknowledgement, Profile.

Platform: Tenants, Plans/limits, Feature flags, Health, Content versions, Break-glass audit.

## 3. Сценарии проверки

В портале приемки реализованы пошаговые кликабельные сценарии UC-01...UC-05 из исходного ТЗ и дополнительные демонстрационные сценарии по обходам, документам, RBAC, ручной проверке attendance и подтверждению отчета.

## 4. Фиксация результата

Для каждого сценария заказчик проходит шаги без пояснений разработчика и отмечает: завершен/не завершен, непонятный шаг, недостающая информация, замечание к терминологии. Целевой критерий исходного ТЗ - не менее 80 процентов критических задач выполняются без помощи.

## 5. Текущий статус

Структурные кликабельные прототипы подготовлены. Финальный UI/UX дизайн в Figma не входит в данный комплект и должен быть добавлен перед окончательной передачей Этапа 1 на приемку, если стороны ожидают согласование визуального дизайна в составе прототипов.
