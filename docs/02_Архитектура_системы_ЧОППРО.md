# Архитектура системы ЧОППРО

## 1. Архитектурный стиль

ЧОППРО реализуется как модульный монолит с единым REST API. Выделение микросервисов допускается только после появления измеряемой нагрузки или организационной необходимости.

## 2. Контейнеры

Admin Web и Client Portal работают через единый REST API на чистом PHP. Мобильный контур реализуется отдельными приложениями для Android и iOS. MySQL 8 хранит транзакционное состояние. Redis используется для кэша, rate limit и очередей. S3 используется для файлов. Внешние уведомления подключаются через адаптеры.

## 3. Multi-tenant

Все бизнес-таблицы tenant содержат `tenant_id`. Tenant определяется из серверной сессии. Для object scoped ролей дополнительно проверяется список доступных объектов. Ограничение применяется одинаково в API, отчетах, экспортах и поиске.

## 4. Авторизация

Веб-пользователи используют логин/пароль и MFA для привилегированных ролей. Охранник использует номер телефона и OTP. Сервер хранит хэш токена сессии. Сессию можно отозвать по пользователю или устройству.

## 5. Offline

Офлайн-событие получает UUID, `client_time`, `idempotency_key`, порядковый номер и payload. Сервер отдельно фиксирует время получения. Исходное время устройства не переписывается.
