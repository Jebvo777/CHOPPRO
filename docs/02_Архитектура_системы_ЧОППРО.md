# Архитектура системы ЧОППРО · реализованный контур

Актуализировано 09.10.2026 по контрольной реализации `d96fe5e84e02`. Система — модульный монолит PHP 8.3 / PDO с единым REST JSON API `/v1`, MySQL 8/InnoDB и самостоятельными веб- и мобильными клиентами. Laravel не используется.

## Контейнеры и хранилища

| Компонент | Реализация и назначение |
|---|---|
| Admin / Client / Platform / Jobs Web | PHP, HTML, CSS, JavaScript; отдельные приложения и сессии, общая БД |
| Android / iOS | Общий проект React Native, Expo и TypeScript; нативные сборки, QR/GPS, фото/аудио, офлайн-очередь |
| Backend | `backend/src/Stage2`; авторизация, tenant/object scope, доменные операции, отчеты, файлы, резервные копии |
| MySQL | Бизнес-данные, идемпотентность, аудит, ограничения частоты, внутренние события и фоновые задания; рабочие миграции 001–008 |
| Приватная файловая система | Документы и вложения, карантин, PDF и зашифрованные копии; файлы выдаются сервером после проверки прав |
| Worker | Контроль сроков и неявок, очередь отчетов, хранение и фоновые операции; регулярный production-cron еще требуется подтвердить |
| Портал и загрузчик | Документы и приложения из целостного проверенного выпуска `main`; незавершенное обновление сохраняет предыдущий выпуск |

Redis и S3 были вариантами проектирования этапа 1; они не требуются текущему рабочему контуру. Подключение внешних провайдеров и доставка уведомлений исключены из текущего объема. Внутренние события и задачи сохраняются.

## Доступ и авторизация

Контекст организации определяется доверенной серверной сессией/токеном. RBAC проверяет разрешения и область объектов одинаково в API, поиске, экспортах, PDF и выдаче файлов. Поддержка получает ограниченный по времени доступ с причиной и аудитом. Веб использует отдельные cookie и CSRF; нативное приложение — Bearer и `X-Choppro-Client: native` без Cookie/Origin. Демонстрационный OTP не подтверждает production-доставку кода.

## Офлайн и неизменяемая история

События и вложения сохраняются на устройстве в зашифрованной очереди. Сервер отдельно хранит исходное и полученное время, проверяет назначение, геозону, QR и порядок действий, устраняет повторы по ключу идемпотентности. Ручное решение создает отдельную запись. Публикация отчета фиксирует версию; изменение создает новый черновик. Заказчик получает только разрешенную опубликованную часть.

## Эксплуатация и доказательства

Контрольная реализация проверена MySQL-интеграцией, сквозными сценариями и нативным запуском в Emulator/Simulator. Зашифрованная копия БД/файлов и восстановление проверены автоматически. Production-размещение, физические устройства, подписанные сборки, независимые копии, RPO/RTO, нагрузка и финальная безопасность подтверждаются отдельными протоколами этапа 4.
