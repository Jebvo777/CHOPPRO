# Реестр технологических решений ЧОППРО

## 1. Назначение

Реестр фиксирует технологические решения, принятые для разработки ЧОППРО, и используется как единая точка сверки архитектуры, документации и реализации.

## 2. Мобильный клиент

Мобильный контур реализован отдельными Android/iOS-приложениями на React Native, Expo и TypeScript. Переданы тестовый Android APK и iOS Simulator 3.0.2; production-подпись и физические устройства остаются для этапа 4.

## 3. Backend

Backend реализуется на PHP 8.3+ без Laravel. Доступ к MySQL выполняется через PDO и подготовленные запросы. HTTP, доменная и инфраструктурная логика разделяются по модулям.

## 4. Web Admin и Client Portal

Admin Web и Client Portal реализуются на PHP, HTML, CSS и JavaScript и взаимодействуют с серверной частью через REST JSON API.

## 5. База данных

Основное транзакционное хранилище - MySQL 8/InnoDB/utf8mb4. Геозоны реализуются средствами MySQL Spatial и/или прикладным расчетом расстояния.

## 6. Очереди и фоновые задачи

В текущей реализации этапов 2–4 очередь внутренних событий, заданий отчетов и ограничения частоты хранятся в MySQL; Redis не требуется. PHP worker выполняет пересчёт сроков, выявление неявок и очистку по сроку хранения; повторы не создают дубликаты. Доставка уведомлений, включая in-app, SMS/OTP, email и push, и прочие внешние интеграции исключены из текущего рабочего объема. Внутренние события и контроль сохраняются. Договорное изменение действует после подписания допсоглашения № 3.

## 7. Архитектурный стиль

Система реализуется как модульный монолит с единым REST API. Выделение отдельных сервисов допускается только при появлении измеряемой нагрузки или организационной необходимости.

## 8. Формат UI/UX

Figma исключена из работ. UX/UI поставляется в виде интерактивных HTML/CSS/JS-прототипов, версионируемых в GitHub.

## 9. Портал проекта

GitHub является источником содержимого портала: документов, разделов, OpenAPI, сценариев, требований, приемки и прототипов. Портал автоматически публикует целостный комплект из одного коммита, проверяет Git SHA файлов и сохраняет предыдущий комплект при ошибке обновления.

## 10. Текущее поведение

[Актуальная спецификация версии 3.0](Актуальная_спецификация_ЧОППРО.md) фиксирует карту Яндекса без ключа API, полный сценарий присутствия, платформу, аудит, трёхлетнее хранение и автоматические миграции.

## 11. Файлы, хранение и финальная поставка

Файлы находятся в приватной файловой системе с метаданными и контрольными суммами в MySQL; S3 не требуется текущей реализации. Техническое хранение — три года с правилами категорий и сохранением действующих/незавершенных процессов. Зашифрованное резервное копирование и восстановление проверены автоматически; регулярный production-cron, отдельное хранение и измеренные RPO/RTO требуют финального протокола.

## 12. Договорный статус

Реестр описывает фактические технические решения и рабочие уточнения. Отчеты и проект соглашения не подтверждают их подписание. Изменение договорного объема и исключения Must/AT действуют в пределах подписанных соглашений. Платеж за этап 4 следует после завершения и финальной приемки; production-сборки входят в основной объем, фактическая публикация обоих приложений оплачивается отдельно по п. 4.11 договора.
