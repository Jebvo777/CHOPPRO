# Реестр отклонений от исходного ТЗ и договорной редакции

## 1. Назначение

Реестр отделяет исходные рекомендации ТЗ заказчика от согласованной/принятой архитектуры ЧОППРО и фиксирует пункты, требующие отдельного подтверждения заказчика.

## 2. Мобильный клиент

Исходное ТЗ: PWA охранника, нативные приложения вынесены за MVP. Договорная редакция: отдельные Android и iOS приложения на React Native. Проектное решение: React Native с отдельными Android/iOS сборками. Статус: соответствует договорной редакции.

## 3. Backend

Исходное ТЗ: NestJS/TypeScript либо эквивалентный типизированный framework. Договорная редакция: PHP/Laravel. Проектное решение: чистый PHP 8.3+ без Laravel и без серверного framework. Статус: техническое решение зафиксировано в проекте, но по текущему тексту договора это отклонение от упоминания Laravel. Для исключения спора при приемке требуется письменное согласование заказчика/уточнение договорной редакции до подписания акта Этапа 1.

## 4. Web Admin и Client Portal

Исходное ТЗ: React/Next.js либо эквивалент. Договорная редакция: web на PHP/Laravel. Проектное решение: server-rendered PHP/HTML/CSS/JavaScript без Laravel. Статус: требует того же письменного согласования, что и backend без Laravel.

## 5. База данных

Исходное ТЗ: PostgreSQL + PostGIS. Договорная редакция: MySQL 8. Проектное решение: MySQL 8/InnoDB/utf8mb4. Геозоны реализуются средствами MySQL Spatial и/или прикладным расчетом расстояния. Статус: соответствует договорной редакции.

## 6. Очереди

Исходное ТЗ: Redis + BullMQ либо эквивалент. Проектное решение: Redis и собственный PHP worker/outbox без BullMQ. Статус: допустимая замена технологического механизма при сохранении требований идемпотентности, повторов и дедупликации.

## 7. Архитектурный стиль

Исходное ТЗ рекомендует модульный монолит. Проект сохраняет модульный монолит. Статус: без отклонения.
